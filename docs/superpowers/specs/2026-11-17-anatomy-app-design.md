# 신체 해부학 앱 (Anatomy) 설계

## 의도와 이유
몸의 구조가 궁금한 일반 사용자가 몸 그림의 부위를 눌러 보며 "이게 여기 있고 이런 일을 하는구나"를 자연스럽게 알게 하는 교양용 앱. 시험 대비용이 아님.

## 목표
- 앞면·뒷면 몸 그림에서 부위를 눌러 이름, 하는 일, 재미있는 사실을 본다.
- 근육계와 골격계를 전환해서 본다. (첫 버전에 둘 다 포함 — 사용자 결정)
- 아이폰에서 앱처럼 쓴다. (Safari "홈 화면에 추가")
- 나중에 3D 모델을 얹을 수 있는 구조.

## 비목표 / 안티 목표
- 퀴즈, 계정, 의학 조언 없음. 설명은 교양 수준으로 정확하고 쉽게.
- 장기계는 첫 버전에서 제외 (후속).
- 정밀한 사진/의학 도판 수준은 목표가 아님. 깔끔한 도식 스타일이 목표.
- 안티 목표: 부정확한 해부학 정보, 3D 모델 확보에 발목 잡혀 출시 못 하는 것.

## 제약
- 개인 Apple ID 무료 계정: 기기당 3개 설치 제한, 7일 서명 만료, 이미 3개 사용 중. 유료 가입 안 함 → 네이티브 앱 불가.
- 무료 배포 (GitHub Pages).

## 접근법 (Approaches)
- **A. SwiftUI 네이티브**: 3D 확장에 유리하나 설치 슬롯·7일 만료 때문에 제외.
- **B. 웹앱 (HTML/CSS/JS + SVG)**: 슬롯·만료 없음, 무료 배포, 3D는 three.js로 확장 가능. **선택됨.**
- React Native / Flutter: 규모에 비해 과해서 제외.
- 일러스트: 직접 만든 단순화 벡터(SVG). 저작권 문제 없고 부위별 터치 영역을 정확히 나눌 수 있음. 사진 수준 정밀도는 포기.

## 사용자가 정한 것
- 일반 교양 목적, 2D 먼저 → 3D 나중, 웹앱(B), 근육+뼈 모두 첫 버전에 포함.

## 내가 정한 것 (확인 필요)
- 빌드 도구 없는 순수 HTML/CSS/JS + SVG (의존성 0).
- 부위를 누르면 아래에서 올라오는 시트에 정보 표시.
- 한국어 설명 + 영어/라틴어 용어 병기.
- 부위 데이터는 JSON 한 파일로 분리 (나중에 3D·장기 추가 시 재사용).
- 처음엔 부위 30개 안팎.
- 호스팅은 GitHub Pages.

## 빌더에게 맡기는 것
- 화면 세부 디자인, 색상, 애니메이션.
- 부위 목록의 구체적 선정과 설명 문구 작성.
- 파일 구성과 SVG 구조.
