# 몸 탐험 3D: 층별 인체 해부 웹앱 설계

이 문서는 `2026-11-17-anatomy-app-design.md`(2D 버전)를 대체한다. main에 있는 2D 앱을 이 작업으로 교체한다.

## 의도와 이유
2D 버전을 써 본 사용자의 평가는 "내용이 없고 유치원생 그림 같다"였다. 원하는 것은 **층별로 벗겨 볼 수 있는, 전문적으로 보이는 인체 해부 앱**이다. 대상은 여전히 일반 교양 목적의 사용자지만, 보이는 수준과 정보의 깊이는 전문 해부학 앱(Complete Anatomy, Z-Anatomy)에 가까워야 한다. 아이폰 Safari에서 홈 화면에 추가해 쓴다. 무료 Apple ID로는 네이티브 앱을 둘 자리가 없어서 웹앱이다.

## 목표
- 실제 인체 데이터 기반 3D 모델을 손가락으로 돌리고, 확대하고, 이동하며 본다.
- 층을 켜고 끄며 피부 → 근육 → 뼈 → 장기 → 혈관 → 신경 순으로 벗겨 본다.
- 어떤 구조물이든 눌러서 이름을 보고, 주요 구조물은 한국어로 전문 정보를 본다.
- 선택한 구조물을 숨기거나, 그것만 따로 보거나, 모두 다시 보이게 할 수 있다.

## 비목표
- 퀴즈, 계정, 의학 조언.
- 검색 기능(다음 버전 후보).
- 움직임 애니메이션, AR, 단면 보기.
- 오프라인 동작과 서비스 워커 캐시.
- 모든 구조물에 한국어 설명을 다는 것.
- Z-Anatomy의 3D 글자 라벨, 기준선·기준면, 부위(region) 표시.

## 안티 목표 (기술적으로 동작해도 실패인 것)
- 아이폰에서 버벅이거나, 처음 여는 데 오래 걸려 쓰기 싫어지는 것.
- 부정확한 해부학 정보.
- 라이선스 표기 누락.
- 각진 저폴리곤처럼 보이거나 "직접 그린 티"가 나는 시각 표현.

## 데이터 조사 결과 (2026-11-17, 실제로 받아서 확인함)
- **BodyParts3D PART-OF (62MB)**: 1258개 메시. 혈관, 장기, 뇌, 뼈, 피부(몸 전체를 덮는 메시 1개, `FJ2810`, 약 20만 삼각형)는 있다. 몸의 근육은 21개뿐이고 신경은 없다. IS-A 목록에서도 넓은등근, 배곧은근, 깨물근, 말초신경이 빠져 있다. 그래서 주 데이터로는 쓰지 않는다. 파일 머리글에는 CC BY-SA 2.1 JP가 적혀 있지만, 공식 라이선스 페이지는 현재 CC BY 4.0이다.
- **Z-Anatomy (`Startup.blend`, 307MB, CC BY-SA 4.0)**: Blender 5.3.0에서 열린다. 메시 4569개, 베벨 곡선 951개가 있다.
  - 근육(789개 메시, 약 210만 삼각형)은 넓은등근, 배곧은근, 깨물근까지 갖추고 있다.
  - 뼈(1244개), 관절과 인대, 심장, 장기, 림프, 중추신경이 있다.
  - 말초신경(정중신경, 넙다리신경, 궁둥신경, 미주신경 등)과 혈관(대동맥, 넙다리동맥, 큰두렁정맥 등)은 굵기가 있는 곡선이라 메시로 바꿀 수 있다.
  - 피부 메시는 없다. 털과 손발톱만 있다.
  - 이름 접미사 규칙: `.l`/`.r` = 좌/우, `.j` = 좌우나 부분을 합친 전체 메시, `.ol`/`.or` = 이는곳(origin) 표시 메시, `.el`/`.er` = 닿는곳(end) 표시 메시, `.i` = 뼈의 지형 표시. `.g`/`.t`/`.s`는 글자 라벨이다.

## 제약
- 호스팅: GitHub Pages(무료, 파일당 100MB 제한). 빌드 서버 없음.
- 런타임: 정적 파일만 쓴다. 빌드 도구 없이 ES 모듈을 쓰고, three.js는 버전을 고정해 프로젝트 안에 넣는다.
- 변환은 이 Mac에서 Blender 5.3.0을 화면 없이 실행하는 파이썬 스크립트로 한다. 재현할 수 있게 스크립트를 저장소에 넣는다. 원본과 중간 산출물은 `.cache/`에 두고 저장소에는 넣지 않는다.
- 라이선스:
  - 변환된 모델 파일(`model/`)은 CC BY-SA 4.0으로 배포한다. 앱 코드는 별도다.
  - 앱 안의 정보 화면과 README에 다음을 모두 표기한다.
    - "Z-Anatomy (Gauthier Kervyn, Marcin Zielinski), CC BY-SA 4.0"
    - "BodyParts3D, © The Database Center for Life Science licensed under CC Attribution 4.0 International"
  - BodyParts3D 표기는 Z-Anatomy의 원천이면서 피부 메시를 직접 가져다 쓰기 때문이다.

## 접근법 (Approaches)
- **A. BodyParts3D만 사용**: 라이선스가 가장 자유롭지만 근육 일부와 신경이 없어서 층별 경험이 성립하지 않는다. 조사 후 기각했다.
- **B. Z-Anatomy를 주 데이터로, 피부만 BodyParts3D에서 가져온다 (선택됨)**: 여섯 층이 모두 갖춰진다. 모델 파일에 SA 조건이 붙지만, 무료 공개 앱이라 실제 부담은 출처 표기와 라이선스 명시 정도다.
- C. 기존 2D 방식 개선: 전문적 표현이 불가능해서 기각했다.

## 사용자가 정한 것
- 일반 교양 목적이지만 전문적인 표현과 내용을 원한다.
- 3D 모델로 간다. 2D는 교체한다.
- 데이터는 조사 후 Z-Anatomy를 확인하기로 했고, 이 문서의 승인으로 B안이 확정된다.
- 웹앱, GitHub Pages, 아이폰 홈 화면.

## 설계 (내 판단: 승인 대상)

### 층(layer)
| 층 | 한국어 | 원천 |
|---|---|---|
| skin | 피부 | BodyParts3D `FJ2810` (Z-Anatomy 좌표계에 맞춰 정렬) |
| muscle | 근육 | Z-Anatomy "4: Muscular system"의 `.l`/`.r`/접미사 없는 메시 |
| bone | 뼈 | "1: Skeletal system" + "3: Joints"(연골·인대) |
| organ | 장기 | "8: Visceral systems" + 심장 + "6: Lymphoid organs" |
| vessel | 혈관 | "5: Cardiovascular system"의 곡선을 메시로 바꾼 것 |
| nerve | 신경 | "7: Nervous system & Sense organs" (뇌·척수 메시 + 말초신경 곡선) |

- 한 구조물은 한 층에만 속한다. `.j`, `.i`, `.o*`, `.e*`, 글자, 기준선, 부위 표시는 화면용 메시에서 제외한다.
- 이는곳과 닿는곳 메시(`.o*`, `.e*`)는 별도 파일로 만든다. 근육을 선택했을 때 뼈 위에 이는곳과 닿는곳을 색으로 보여 준다. 이것이 이 앱의 대표 장면이다.
- 피부 정렬: BodyParts3D와 Z-Anatomy의 뼈 하나(예: 넙다리뼈)의 경계 상자를 비교해 변환 행렬을 구한다. 눈으로 확인했을 때 어긋나면 피부 층을 빼고 사용자에게 알린다.
- 처음 열면 근육과 뼈 층만 내려받아 켠다. 나머지 층은 켤 때 내려받는다.
- 층 버튼을 누를 때마다 켬 → 반투명 → 끔 순서로 바뀐다.

### 변환 결과물
- 층마다 glb 파일 하나: `model/<layer>.glb`. 메시 이름은 Z-Anatomy 객체 이름(예: `Median nerve.l`)을 그대로 쓴다.
- meshopt로 압축하고, 런타임에서 MeshoptDecoder로 푼다.
- `model/index.json`: 메시 이름 → { 영어 이름(접미사 제거), 좌우, 층, 상위 묶음 이름(예: "Anterior compartment of arm") }.
- 품질이 용량보다 우선이다. 단순화는 눈에 띄는 각짐이 생기지 않는 범위에서만 한다.
- 목표: 근육+뼈 첫 로딩은 압축 전송 크기 20MB 이하, 동시에 표시되는 삼각형은 약 150만 개 이하. 넘치면 먼저 작은 구조물(인대, 활액주머니)을 줄이거나 빼고, 그다음 단순화한다.

### 화면과 조작
- 화면 전체가 3D 뷰다. 위에는 층 버튼 줄, 아래에는 선택 정보 시트가 있다.
- 한 손가락으로 회전, 두 손가락으로 확대·이동, 두 번 탭하면 시점을 초기화한다.
- 구조물을 탭하면 선택한다. 강조색으로 표시하고 시트를 반쯤 연다. 빈 곳을 탭하면 선택이 풀린다.
- 시트의 동작: "숨기기", "이것만 보기", "모두 보이기".
- 근육을 선택하면 이는곳과 닿는곳을 뼈 위에 표시한다(위 참조).
- 정보 버튼에서 출처와 사용법을 보여 준다.
- 성능 목표: 사용자의 아이폰에서 회전이 끊기지 않는 것. 사용자가 같은 와이파이에서 로컬 서버에 접속해 직접 확인하고, 그 결과가 완료 조건이다.

### 내용
- `data/content.json`: 한국어 내용. 키는 접미사를 뗀 영어 이름(예: `Biceps brachii muscle`)이다. 좌우는 같은 내용을 쓴다.
- 공통 필드: 한국어 이름, 영어 이름, 라틴어 이름, 쉬운 설명 1~2문장, 재미있는 사실(선택).
- 근육: 이는곳, 닿는곳, 작용, 신경 지배. 뼈: 주요 부위, 이어지는 관절. 장기·혈관·신경: 기능, 위치 관계.
- 처음에는 주요 구조물 약 80개에 한국어 내용을 단다. 근육·뼈 위주로 하되, 각 층마다 대표 구조물을 넣는다. 2D 버전의 31개는 옮기고 보강한다.
- 라틴어 이름은 Z-Anatomy의 `TA2.csv`(국제 해부학 용어)를 참고할 수 있다. 쓰기 전에 그 파일의 라이선스를 확인한다.
- 한국어 내용이 없는 구조물은 영어 이름, 층, 상위 묶음을 보여 준다. "준비 중" 같은 문구는 쓰지 않는다.
- 정확성: 표준 해부학 지식(Gray's Anatomy, Terminologia Anatomica)으로 쓴다. 근육의 네 항목은 모두 한 번씩 교차 확인한다. 최종 리뷰어가 내용을 따로 검토한다. 해부학 전문가의 검토는 없다.
- 용어: 대한해부학회 용어를 기준으로 하고, 흔히 쓰는 한자어를 괄호로 함께 적는다.

### 저장소와 교체
- 아직 배포된 적이 없다. 같은 저장소에서 브랜치로 작업하고 main의 2D 앱을 교체한다.
- 아이콘, 매니페스트, README는 이어서 고쳐 쓴다. 2D 전용 코드와 테스트는 지운다.
