# 몸 탐험 v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 남/여 전환(여성 골반 장기), 패널 분할과 연결된 구조물, 검색, 부위 바로가기, 이름표, 가로 단면을 추가한다.

**Architecture:**
- 변환: 여성 장기는 Blender에서 HRA glb를 불러와 Z-Anatomy 골반에 정렬하고 `female.glb`로 내보낸다. 성별 표시는 `zanat_rules.sex_for`로 index에 기록한다.
- 런타임: 판단 로직은 순수 모듈로 만든다(`search.js`, `related.js`, `labels.js`, `regions.js`, `sex.js`, `clip.js`). three.js 쪽은 `viewer.js`에, 화면 연결은 `app.js`에 둔다.

**Tech Stack:** v1과 같다(three.js 0.170.0 vendor, Blender 5.3, gltf-transform, node --test, unittest).

**Spec:** `docs/superpowers/specs/2026-11-18-anatomy-v2-design.md`

## Global Constraints
- 여성 데이터: `.cache/hra/VH_F_{Uterus,Ovary_L,Ovary_R,Fallopian_Tube_L,Fallopian_Tube_R,Urinary_Bladder,Pelvis}.glb`
  - glTF 기준 y 위, +z 앞, 미터 단위이고 모든 장기가 골반 좌표계를 공유한다.
  - CC BY 4.0. 인용: "Browne, K., Schlehlein, H., Herr II, B. W., Quardokus, E., Bueckle, A., Börner, K. (2022). HuBMAP CCF 3D Reference Object Library."
- 여성 메시 이름(정확히):
  - `Uterus`
  - `Ovary.l`, `Ovary.r`
  - `Uterine tube.l`, `Uterine tube.r`
  - `Urinary bladder (female)`
  - 모두 organ 층, `sex: "female"`이다.
- 남성 전용(`sex: "male"`): 장기층의 group `Genital systems'` 전체, `Urethra`, `Urinary bladder`, 그리고 이름에 `penis|penile|testicular|scrot|cremaster`가 들어간 메시.
- 여성 모드에서는 skin 층 버튼을 비활성화하고 안내한다: "여성 모드에서는 피부층을 지원하지 않아요".
- 글자 크기: 제목 1.25rem, 본문 0.875rem, 표 0.8125rem.
- 넓은 화면(≥700px) 패널: 위 설명 60%, 아래 연결된 구조물 40%이고, 칸마다 따로 스크롤한다.
- 이름표 최대 24개, 단면은 가로(높이 기준) 하나다.
- 퀴즈·질환·계정·의학 조언 없음.

## Review Focus
1. **여성 모드에서 남성 전용 메시가 검색·이름표·탭으로 선택되지 않음.** 검색에서 고르면 성별이 바뀐다. (Task 3 `visibleForSex`, `resolveTarget` 테스트)
2. **단면 위로 잘린 부분은 탭해도 선택되지 않음.** 아래쪽 구조물이 선택된다. (Task 3 `belowClip` 테스트)
3. **이름표끼리 겹치지 않고 24개를 넘지 않음.** (Task 3 `placeLabels` 테스트)
4. **연결된 구조물이 꺼진 층에 있음** → 층을 켜고 이동한다. 실패하면 v1과 같은 안내를 띄운다. (Task 3 `resolveTarget` + Task 5 수동)
5. **related의 모든 base가 index에 존재함.** (Task 2 `validateContent` 확장 테스트)

### Task 3: 순수 로직
**Files:** `js/search.js`, `js/related.js`, `js/labels.js`, `js/regions.js`, `js/sex.js`, `js/clip.js` + 각 테스트
- `search(query, index, content, {limit=20}) -> [{mesh, title, subtitle}]`:
  - 완전 → 앞부분 → 포함 순이고, 한국어 내용이 있는 항목이 먼저다.
  - 초성 매칭을 지원한다(`toChoseong`).
  - 좌우가 있으면 `.r`을 대표로 쓴다.
  - 같은 base는 한 번만 낸다.
- `relatedFor(meshName, index, content) -> [{type, items:[{mesh, title}]}]`:
  - 내용이 있으면 related를 쓰고, 각 base의 대표 메시를 고른다(선택한 메시와 같은 쪽 우선).
  - 내용이 없으면 같은 group 최대 8개를 `type: '같은 부위'`로 낸다.
- `placeLabels(cands:[{mesh,x,y,w,h,dist}], max=24) -> mesh[]`: 화면 중앙에서 가까운 순으로 놓고, 겹치면 건너뛴다.
- `REGION_PRESETS`: 10개 `{id, label, target:[x,y,z], distance, dir:[x,y,z]}`. 유효성 테스트로 확인한다: 10개, 고유 id, target y 0~1.85, dir 단위 벡터.
- `visibleForSex(info, sex) -> bool`, `resolveTarget(mesh, index, {sex, layers}) -> {sex, layersToTurnOn}`
- `belowClip(pointY, clipY|null) -> bool`
- [ ] 각 RED → GREEN, 커밋
