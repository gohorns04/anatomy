# 몸 탐험 3D Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** main의 2D 앱을, Z-Anatomy 기반 층별 3D 인체 해부 웹앱으로 교체한다. 층은 피부, 근육, 뼈, 장기, 혈관, 신경이다.

**Architecture:**
- 오프라인 변환 파이프라인: Blender 5.3 헤드리스 파이썬으로 층별 glb를 뽑고, Node(gltf-transform)로 meshopt 압축한다.
- 런타임: 빌드 없는 정적 사이트다. three.js 0.170.0을 vendor하고, importmap으로 불러온다.
- 판단 로직(층 분류, 층 상태, 보이기 규칙, 선택 정보 렌더링, 이는곳·닿는곳 매핑)은 순수 함수로 두고 테스트한다. three.js 장면은 브라우저와 실기기에서 확인한다.

**Tech Stack:** Blender 5.3.0(bpy), Python 3 `unittest`, Node 26 `node --test`, `@gltf-transform/core|functions|extensions` + `meshoptimizer`(개발 전용), three.js 0.170.0(vendor).

**Spec:** `docs/superpowers/specs/2026-11-17-anatomy-3d-design.md`

## Global Constraints

- 작업 브랜치: `feat/anatomy-3d`. 완료 후 main의 2D 앱을 교체한다.
- 원본은 `.cache/zanatomy/Z-Anatomy/Startup.blend`와 `.cache/bp3d/obj/partof_BP3D_4.0_obj_99/FJ2810.obj`(피부)를 쓴다. `.cache/`는 커밋하지 않는다.
- 층 id와 한국어 이름: `skin` 피부, `muscle` 근육, `bone` 뼈, `organ` 장기, `vessel` 혈관, `nerve` 신경. 버튼 순서도 이 순서다.
- 층 상태는 `on` → `ghost` → `off` → `on` 순으로 돈다.
- 첫 로딩에서는 `muscle`과 `bone`만 내려받아 `on`으로 둔다. 나머지 층은 `off`이고, 처음 켤 때 내려받는다.
- 첫 로딩 예산: `model/muscle.glb` + `model/bone.glb` ≤ 20MB(20 × 1024 × 1024 바이트). 단순화는 눈에 띄는 각짐이 생기지 않는 범위에서만 한다.
- 메시 이름은 Z-Anatomy 객체 이름을 그대로 쓴다(예: `Median nerve.l`). 피부만 `Skin`이다.
- 출처 문구 두 개는 그대로 표기한다.
  - `Z-Anatomy (Gauthier Kervyn, Marcin Zielinski), CC BY-SA 4.0`
  - `BodyParts3D, © The Database Center for Life Science licensed under CC Attribution 4.0 International`
- `model/`은 CC BY-SA 4.0이다(`model/LICENSE.txt`).
- 런타임에는 npm 패키지가 없다. three.js 파일만 `vendor/three/`에 넣는다.
- 한국어 내용이 없는 구조물에 "준비 중" 같은 문구를 쓰지 않는다.
- 퀴즈, 계정, 의학 조언, 검색, 오프라인 캐시는 넣지 않는다.

## Review Focus

1. **반투명(`ghost`)이나 꺼진(`off`) 층의 메시를 탭함** → 선택되지 않는다. 반투명 피부 너머의 근육을 누르면 근육이 선택된다. (Task 5 `isPickable` 테스트)
2. **층 파일 로드 실패**(네트워크 끊김) → 그 층 버튼은 `off`로 돌아가고 "○○ 층을 불러오지 못했어요. 다시 눌러 보세요." 안내가 뜬다. 다른 층은 계속 쓸 수 있다. (Task 6 `nextLayerState`의 `loadFailed` 테스트 + Task 7 수동 확인)
3. **"이것만 보기" 상태에서 층을 바꿈** → 숨김 목록은 그대로고, "모두 보이기"를 누르면 숨김이 전부 풀린다. 선택한 구조물이 꺼진 층에 속하게 되면 선택이 해제된다. (Task 5 `applyLayerChange` 테스트)
4. **한국어 내용이 없는 구조물** → 영어 이름, 층 이름, 상위 묶음만 보여 주고 "준비 중" 같은 문구는 없다. (Task 6 `renderInfo` 테스트)
5. **왼쪽·오른쪽 근육 선택** → 같은 한국어 내용이 나오고, 이는곳·닿는곳은 선택한 쪽 것만 표시된다. (Task 5 `insertionNamesFor` 테스트)

**Interfaces:**
- Produces (`tools/zanat_rules.py`):

### Task 5: 보이기·선택 규칙 (순수 로직)

**Files:**
- Create: `js/visibility.js`, `tests/visibility.test.js`

**Interfaces:**
- Produces:
  - `isPickable(meshName, index, layerStates, hidden: Set) -> boolean` — 층 상태가 `on`이고 hidden에 없을 때만 true.
  - `applyLayerChange(state, layer, newLayerState, index) -> state`
    - `state = { layers: {[layer]: 'on'|'ghost'|'off'}, hidden: string[], selected: string|null }`
    - 선택된 메시의 층이 `off`가 되면 `selected = null`이다. `ghost`면 선택을 유지한다.
  - `hideSelected(state) -> state` — selected를 hidden에 넣고 selected를 null로.
  - `isolateSelected(state, index) -> state` — selected 외의 모든 메시(전 층)를 hidden으로. selected는 유지한다.
  - `showAll(state) -> state` — hidden을 비운다.
  - `insertionNamesFor(meshName, insertionNames: string[]) -> { origins: string[], insertions: string[] }`
    - base와 side가 같은 `.o<side>`, `.e<side>` 이름을 찾는다. base가 근육 전체 이름(예: `Biceps brachii muscle`)이면, 그 base를 포함하는 부분 이름(`Long head of biceps brachii`)도 찾기 위해 index의 group이 같은 메시들의 base도 함께 본다. 빌더는 실제 데이터에서 표본 5개 근육으로 확인한 규칙을 ledger에 남긴다.
- [ ] **Step 1: 실패하는 테스트** (Review Focus 1, 3, 5):
  - ghost 층 메시는 isPickable false, on 층은 true, hidden이면 false
  - 선택된 근육이 있을 때 muscle을 off로 바꾸면 selected null, ghost로 바꾸면 유지
  - isolate 후 층을 바꿔도 hidden 유지, showAll로 비워짐
  - hideSelected 후 selected null, hidden에 포함
  - `insertionNamesFor('X muscle.l', ['X muscle.ol','X muscle.el','X muscle.or','Y.ol'])` → origins `['X muscle.ol']`, insertions `['X muscle.el']`
- [ ] **Step 2:** FAIL → 구현 → PASS
